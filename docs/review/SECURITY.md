# Round 2 — entire-project security review

Reviewed the application at `011f1cd` and patched the findings below on `work`. Scope: every source module in both Rust crates, browser code/styles/API client, both SDKs, simulator and replay verifier, backup/dev/load/smoke scripts, dependency lockfiles, configuration/docs and CI. Public discovery data and resolved game state are deliberately public; live bids, future cards and bearer credentials are confidential. The operator and host OS remain trusted.

## Findings and resolution

| ID / severity | Shortcoming and impact | Resolution / evidence |
| --- | --- | --- |
| S01 / high | WebSockets accepted `create_team` while registration limits applied only to HTTP. Six registrations succeeded on one socket despite the documented five/minute limit. | WS now permits only auth/watch/ping and participant gameplay. Public registration and owner/operator operations use HTTP admission with shared IP limits. Real-network regression rejects every WS registration attempt and the sixth HTTP registration. |
| S02 / high | Two engines could open the same database. Reproduced the second engine recovering a match to `aborted` and exposing its seed while the first still played it. Ratings could also diverge. | Lifetime OS lease on the actual DB inode before opening/recovery, retained until connection shutdown. A second engine fails closed, including alternate paths to the same inode. Unit and real-process regressions. Backups remain read-only and compatible. |
| S03 / medium | Public reads, control operations and WS control frames could bypass useful admission budgets and compete with bidding; thousands of slow HTTP requests had no application deadline. | Host/origin checks before parsing; bounded concurrent HTTP/WS work, read/command/control/registration/handshake budgets, per-peer sockets, five-second HTTP timeout, and all WS sends (including pong/initial state) have timeouts. Disconnected queued callers are skipped. Round 3 moves archives/rosters/rankings/tournaments to a bounded read-only worker, caches only public metadata and caps pages (100 bots/ranks, 10 tournaments); read load cannot occupy the bidding writer queue. |
| S04 / medium | Host-derived origin acceptance alone permitted DNS-rebinding to a private installation. | Independent explicit hostname allowlist on every route; loopback-only defaults; exact additional origin allowlist. Reject `null`/foreign origins and attacker Host headers. Native bot clients may omit Origin but still need valid credentials for mutations. |
| S05 / medium | Mutation/secret responses lacked `Cache-Control: no-store`; browser owner credentials were automatically persisted in session storage; connect CSP allowed arbitrary ws/wss destinations. | No-store API responses/client fetches, redirect-refusing client fetches, owner credentials held only in memory, legacy session value cleared, same-origin connect CSP, frame denial and restricted browser permissions. React escapes names; no HTML injection APIs or untrusted executable templates exist. Inline *styles* remain for progress indicators, with scripts restricted to self. |
| S06 / medium | Count-only receipt cache could retain large account responses and credential receipts indefinitely under light load. | Do not cache auth/account reads or anonymous registration; 4 MiB/2048-entry budget, 64 KiB per receipt and 120-second expiry. Expiry runs even without new commands. Revalidate credentials before returning cached mutations. Tests cover expiry, byte accounting and read non-accumulation. |
| S07 / medium | Replay verifier accepted insufficiently constrained event chronology and did not validate timeline snapshots; stdin was unbounded. | Library verifier now requires the initial commitment, exact showdown/consumption phases, one terminal event, consistent status/round/seq, every supplied history checkpoint and final accounting. CLI input <=4 MiB; event/history counts bounded. Tampered phases, history, terminal status and missing commitment rejected. Private bid allocation remains unverifiable by a public transcript. |
| S08 / medium | Endless all-pass/tied tournament replays consumed slots and disk forever. | Three consecutive drawn games suspend a tournament as `attention` without assigning a winner or advancing a bracket. Other active games in that tournament are aborted without ratings; reservations remain until operator review/cancellation. Sponsor amounts, poker ranking, ratings and scoring are unchanged. |
| S09 / medium | Bundled SQLite 3.51.1 predates the WAL-reset corruption fix documented by SQLite. | Upgrade rusqlite 0.38 → 0.43, bundling SQLite 3.54.1. The single writer reduces exposure but does not justify keeping known affected code. See SQLite's primary advisory below. |
| S10 / medium | Python HTTP helper followed redirects with bearer headers; SDKs allowed accidental plaintext credentials to remote hosts. Custom WS parsing had incomplete control-frame/handshake validation and constructor failure cleanup. | Python refuses redirects, bounds HTTP response size and command/handshake wait, closes failed handshakes, validates RFC control frames/JSON shape. Both SDKs require HTTPS/WSS outside loopback unless the user explicitly enables an insecure development override. Tests verify redirect targets receive no Authorization. Native Node WebSocket uses the platform handshake/TLS implementation. |
| S11 / low | Internal SQLite error strings could reach clients; malformed IDs/extra fields were inconsistently checked; large offsets could overflow continuation arithmetic; bidi control characters could spoof names. | Strict per-operation schemas and bounded printable IDs/fields, capped offset, public error-code filtering, and bidi-control rejection. Server request traces omit query strings and headers. |
| S12 / low | DB secrets depended on ambient umask. Backup integrity used `assert`, disabled by `python -O`. CI action refs were mutable and checkout left credentials in git config. | DB created/restricted mode 0600 on Unix; backup performs unconditional integrity validation. Actions pinned to verified commit SHAs; checkout does not persist credentials; read-only CI permission and no self-hosted untrusted-PR runner. Dependabot tracks Cargo/npm/action updates. |

| S13 / medium | Public health/Prometheus counters exposed command/rejection activity, allowing timing correlation with sealed actions. | Public health omits those counters. Metrics are disabled by default and require a separate random 32+ character metrics bearer token; operator credentials do not substitute. HTTP regression checks unauthenticated refusal and minimal health. |
| S14 / low | A hard-restart check found one-ULP rating drift when JSON was parsed without exact float round trips (1459.9298196779387 → 1459.929819677939). | Enable serde_json's `float_roundtrip` feature. A 128-update exact-bits persistence regression and real hard restart preserve ratings exactly. Previously stored rounding differences are not retroactively recalculated. |

## Review of other surfaces

- **Engine/economy:** network commands validate identity, round, liquidity, unique owned cards and cap before mutation. Bids are immutable; invalid actions are atomic; no bid/seed serialization in live snapshots. Exact ties use seed-derived keys independent of arrival order. Checked resource/reward bounds for the finite 52-card match. Exhaustive evaluation and seeded invariants remain in the suite.
- **Authorization:** owner/team, bot/seat and operator roles are independently enforced at the service. Rotation invalidates previous tokens immediately. Failed WS re-auth clears the prior identity. Public replay/history does not imply permission to mutate. No authorization relies on UI state, request IDs, external identity providers or cookies.
- **Persistence/recovery:** parameters bind all SQL values. Public queries omit private seed storage. Completed result/ratings/tournament progression remain atomic, including schema-v2 event/history ledgers. Future schema versions are refused before creating legacy tables. Corrupt replay JSON fails parsing; storage-write failure closes the actor rather than publishing undurable state. Hard and graceful recovery abort live games and never re-rate them. No execution of SQL from user strings.
- **Browser:** no `innerHTML`, `eval`, dynamic executable scripts or HTML templating of names. Credentials never go in links. Owner/operator views hold secrets in memory, with explicit lock/recovery instructions. A same-origin XSS or malicious browser extension could still act with an in-memory secret; passkeys/HttpOnly owner sessions are future design options, not falsely claimed protections.
- **SDKs/tools:** strategies run on participant hardware, no shell commands are built from bot/user names, CLI configuration is local trusted input, and backups refuse an existing destination. Load/smoke tools use isolated local fixtures. No service accepts executable bot uploads or arbitrary callback URLs (avoiding an entire SSRF/code-execution surface).
- **Supply chain:** updated Cargo lock scanned against RustSec (1,509 advisories, DB commit `02e2517f457a359fc6d3440ea4560c8ea188fee8`): zero known vulnerabilities/warnings. npm audit including dev dependencies: zero known vulnerabilities. SQLite's own notice was reviewed separately rather than assuming advisory coverage. Scans are point-in-time, not guarantees.

## Validation

`make check`, Python transport tests, exhaustive evaluator, explicit security unit regressions, `python3 scripts/security_checks.py`, actual Python/TypeScript agents plus full tournament/restart smoke, and Chromium participant/replay flows. The real-network suite checks Host/Origin, invalid schema/offset, transport isolation, registration limits, cache headers, failed auth/rotation, cross-team access, DB leasing and live seed privacy. All fixture credentials stay local/ephemeral.

## Residual risks and operating requirements

TLS termination, real-client ingress rate limits and local-volume permissions are deployment responsibilities. Application budgets use the socket peer, not spoofable forwarding headers; clients sharing an ingress also share those budgets. Installations must configure public allowed hosts. Stop older binaries before upgrading: an older process that does not implement the lease cannot be made to honor it retroactively. No NFS/shared-WAL multi-host deployment.

The trusted operator can choose seeds, see private bids, abort games or alter storage; commitments and public economic replay do not prove private auction allocation. Anonymous teams are not unique humans; collusion, rating farming and Unicode confusables need governance/evaluation, not a false cryptographic guarantee. A loss of the offline owner credential or interrupted owner rotation can require operator-assisted recovery; passkeys/recovery design remains in IDEAS.md. Disk retention is operator-managed, and upstream network/OS resource exhaustion still requires normal ingress/host controls. Advisory locks do not prevent an administrator from modifying files or starting incompatible old software.
